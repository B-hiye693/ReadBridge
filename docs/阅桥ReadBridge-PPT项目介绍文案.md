---

## 一、项目基本信息

**项目名称：** 阅桥 ReadBridge  
**项目定位：** 跨网页、文件和 Windows 应用的 AI 认知无障碍阅读助手  
**核心理念：** 让信息不止“看得见”，更能“读得懂”  
**目标平台：** Windows、Chrome、Microsoft Edge  
**当前形态：** 浏览器扩展 + Windows 桌面客户端 + 本机 FastAPI 服务

### 项目简介

阅桥是一套面向复杂文本理解场景的认知无障碍阅读工具。它能够读取网页、文档、应用选区和屏幕区域中的文字，通过 AI 将复杂内容转换成结构清晰、语言简明、可追溯原文的易读内容，并提供难词解释、重点提取、原文定位和语音朗读等辅助功能。

阅桥不是简单地“缩短文章”，也不是只生成一段摘要。它更关注信息结构、事实完整性和阅读负担：把长段落拆成主题卡片，保留关键人物、数字、条件、风险和不确定性，并让用户随时查看每条结论对应的原文。

## 第 2 页：项目背景——信息可见，不等于信息可理解

### 页面标题

**复杂信息正在制造新的阅读障碍**

### 展示文字

- 网页和文档中存在大量长句、术语、密集段落和复杂结构。
- 学术论文、政策通知、产品说明和新闻报道往往认知负担较高。
- 传统放大、朗读或复制工具解决了“看见”和“听见”，却不一定解决“理解”。
- 用户常常需要在多个软件之间复制、翻译、总结，再回到原文核对。

### 核心结论

**真正的无障碍，不只是让文字可访问，还要让内容可理解、可核对、可操作。**

### 视觉建议

左侧展示一段密集复杂原文，右侧展示阅桥拆分后的易读卡片，中间用桥梁或箭头连接。

## 第 4 页：解决方案概览

### 页面标题

**一个入口，连接不同应用中的文字**

### 展示文字

阅桥提供三种相互配合的使用形态：

1. **浏览器扩展：** 一键读取网页正文，选词解释，并定位回原文。
2. **Windows 桌面端：** 跨应用读取选区、框选 OCR、打开本地文件和调用文件库。
3. **本机 AI 后端：** 统一处理解释、易读重构、语言选择、缓存和神经语音。

### 一句话流程

**获取内容 → 用户确认或编辑 → AI 易读重构 → 卡片化呈现 → 原文核对与语音朗读**

### 视觉建议

绘制三端架构图：网页、文件/应用 → 阅桥本机服务 → AI 与语音服务 → 易读界面。

## 第 5 页：核心功能一——一键易读

### 页面标题

**将复杂长文重构为低认知负担内容**

### 展示文字

- 自动识别文章主题和逻辑结构
- 将长段落拆分为多个主题卡片

- 保留人物、时间、数字、条件、风险和结论
- 明确保留“可能、据称、尚未确认”等不确定性
- 长文自动分块并并行处理，降低遗漏和等待

### 核心差异

**阅桥做的是“认知重构”，不是简单摘要。**

### 视觉建议

## 第 6 页：核心功能二——简单解释与语言转换

### 页面标题

**选中哪里，就解释哪里**

### 展示文字

- 在网页中直接选中词语或段落进行解释
- 在桌面应用中通过全局快捷键读取选区
- 支持先点击“简单解释”，再到其他应用选择内容
- 输出包含简单解释、关键词说明和易懂示例
- 自动判断中英文原文
- 支持“跟随原文、输出中文、Output: English”三种模式
- 用户可先修改识别结果，再提交 AI

### 演讲备注

语言选择与原文语言相互独立。例如，英文论文可以默认生成英文易读内容，也可以切换为中文解释。

## 第 7 页：核心功能三——跨应用取文与 OCR

### 页面标题

**让无法直接复制的内容也能被理解**

### 展示文字

阅桥桌面端支持三条取文路径：

1. **读取选区：** 通过 Windows UI Automation 获取其他应用中的文字选区。
2. **框选识字：** 用户主动选择屏幕区域，在本机完成中英文 OCR。
3. **手动粘贴：** 为不支持自动取文的应用提供稳定后备方案。

### 可靠性设计

- 取文前记录目标窗口和焦点，避免读取阅桥自身内容
- 支持多显示器和不同缩放比例
- 自动区分中文、英文和数字
- 支持取消、空截图和 OCR 不可用提示
- 跳过密码控件并遵守系统权限边界

### 视觉建议

用三张小图分别表示“选区、框选、粘贴”，中间展示 OCR 选框效果。

## 第 8 页：核心功能四——文件全文与文件库

### 页面标题

**把本地文件像网页一样打开和阅读**

### 展示文字

- 支持打开或拖入 TXT、Markdown、HTML、DOCX 和文字型 PDF
- 自动提取全文并进入一键易读流程

## 第 10 页：核心功能六——自然语音与连续朗读

### 页面标题

**从“读得懂”延伸到“听得清”**

### 展示文字

- 支持 Windows 系统语音和 CosyVoice 神经语音
- 提供多种自然男声、女声音色
- 支持语速调节，并显示当前倍速
- 支持朗读全文或单独朗读某个模块
- 支持停止、取消以及失败自动回退
- 首段优先生成，开始播放后在后台预生成后续语音
- 相同内容、音色和语速可命中本机内存缓存

### 实测数据

- 短文本首次神经语音生成约 **2.9 秒**
- 相同内容再次调用可直接命中缓存，响应接近 **0 秒**

### 演讲备注

云端语音本身存在网络和模型生成时间。阅桥通过首段优先和后台预取，避免用户等待整篇音频生成后才开始播放。

## 第 13 页：安全、隐私与使用边界

### 页面标题

**用户主动发起，数据流向清晰可控**

### 展示文字

- 每次取文和截图均由用户主动发起
- OCR 截图只在本机处理，默认不保存、不上传
- 原文和截图默认仅保存在当前会话内存
- API Key 只由本机后端 `.env` 管理，不进入浏览器扩展
- AI 操作只提交用户确认后的文本
- 后端配置云端 Provider 时，文本会发送至相应模型服务
- 密码控件、受保护窗口和更高权限窗口遵守系统安全边界
- 日志记录状态、耗时和文本哈希，不记录完整密钥

### 页面提示

AI 输出用于辅助理解，重要医疗、法律、金融或政策信息仍应核对原文和权威来源。

## 第 14 页：项目创新点与优势

### 页面标题

**阅桥的差异化价值**

### 展示文字

1. **跨应用：** 不局限于单一网页，可连接网页、文件和 Windows 应用。
2. **认知重构：** 以主题卡片、重点和难词解释替代普通大段摘要。

6. **离线可用部分：** 后端离线时仍可取文、OCR、预览和使用系统语音。
7. **稳定性设计：** 快速模型失败后自动精简重试，并回退高质量模型。
8. **响应优化：** 长文并行生成、结果缓存、语音首段优先与后台预取。

# 三、推荐演示流程

如果 PPT 汇报包含现场演示，建议控制在 3～5 分钟：

1. 打开一篇包含长句和专业词的网页。
2. 选中一个复杂词语，展示“简单解释”。
3. 点击“一键易读”，展示主题卡片、重点和难词。
4. 点击“查看对应原文”或定位按钮，说明结果可追溯。
5. 切换中文或英文输出，展示跨语言能力。
6. 打开桌面客户端，将 PDF 或 DOCX 拖入窗口。
7. 展示文件全文、文件库以及左右对照布局。
8. 点击朗读，调整音色和语速，再点击停止。
9. 将客户端收起为悬浮球，展示跨应用使用方式。

演示时建议准备一份可提取文字的 PDF、一张中英数字混合图片和一个普通网页，避免使用受保护网页或扫描质量过低的材料。

# 五、30 秒项目介绍

阅桥 ReadBridge 是一款跨网页、文件和 Windows 应用的 AI 认知无障碍阅读助手。它可以读取网页正文、应用选区、本地文件和屏幕 OCR 文字，把复杂内容重构成主题清晰、语言简明、能够定位回原文的易读卡片，并提供中英文转换、难词解释、文件库和自然语音朗读。阅桥希望解决的不只是“看不见”，更是“看见了却难以理解”的问题。

# 六、1 分钟项目介绍

阅桥 ReadBridge 面向阅读障碍、复杂文本理解困难以及需要高效阅读的人群。用户可以在浏览器中一键读取网页，也可以通过 Windows 桌面端读取其他应用的选区、框选屏幕文字，或者直接打开 PDF、DOCX 等文件。阅桥通过 AI 将长句和密集段落重构为主题卡片，提取重点、解释难词，同时保留每条内容对应的原文依据，方便用户定位和核对。它支持中文、英文和跨语言输出，也支持 Windows 系统语音与神经语音。整个系统由浏览器扩展、WPF 桌面客户端和本机 FastAPI 后端组成，兼顾跨应用能力、隐私边界和离线回退。我们的目标是让数字信息不仅可以访问，而且真正容易理解。
